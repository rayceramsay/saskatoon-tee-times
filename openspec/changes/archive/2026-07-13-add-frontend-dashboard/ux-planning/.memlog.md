- (assumption) Hard UX constraints inherited from architecture: single date-keyed view; client-side filters (course, holes 9/18, players/group-size, earliest-start), sort, group-by-course, fixed-page-size pagination; URL is single source of truth (shareable/bookmarkable); each slot shows course/start/holes/routing/price-per-adult(or unknown)/Book link resolved by selected players; freshness = min scrapedAt 'last updated' + optional per-course staleness; past slots hidden client-side; Next.js static export, <2s, edge-cached.
- (decision) Form factor: responsive web, mobile-first design, but desktop is a first-class surface. Contexts: phone in the kitchen; laptop after work.
- (decision) Stakes: small audience (Rayce + friends) but held to a real consumer-product quality bar — useful and easy to use is the success metric.
- (decision) Density is a core value: maximize tee times visible per screen, maximize space usage, minimize scrolling to evaluate options. To-the-point utility.
- (decision) Desktop layout vision: persistent left filter sidebar that acts as the query form; large scrollable listings table on the right taking most of the screen.
- (decision) DEFAULT-ON results: on open, immediately show today's available tee times across all courses — zero clicks to useful info. Filters are OPTIONAL side refinements, never a gate.
- (override) ANTI-PATTERN to avoid (Chronogolf): forced sequential funnel (date -> course set -> holes -> players -> THEN results). We invert this: results first, refine optionally and non-sequentially without distracting from listings.
- (decision) Default listing organization: chronological across ALL courses (earliest first), with a group-by-course view toggle. Default = mixed chronological.
- (decision) Row visual hierarchy: tee time (the clock) is the dominant scan anchor; course/price/holes/players are secondary metadata. Matches 'I want to play around X o'clock'.
- (assumption) Mobile row format UNDECIDED — user wants to see wireframes of both compact stacked rows vs cards before choosing.
- (decision) DATA-MODEL CLARIFICATION (Rayce): 'Holiday Park Championship' and 'Holiday Park Executive 9' are each a FULL course name (separate courseId), NOT 'Holiday Park' + a routing/qualifier. Routing sets (e.g. Front 9 / Back 9) are a FURTHER split WITHIN a course. So a listing row = full course name + holes + routing(which nine(s)) as distinct elements. Display must never imply course = base+routing.
- (decision) Mobile format CHOSEN: Option A (compact rows). Refinements required: (1) full course name must not truncate/ellipsis — give it priority space; (2) routing sets shown in a distinct way (not crammed into the truncating line); (3) tighten the rest to free up room for the name.
- (decision) DATA-MODEL: multi-nine courses (e.g. The Willows = 3 nines: Bridges/Lakes/Xena) compose an 18-hole round from a chosen ORDERED PAIR of nines (Xena+Bridges, Lakes+Bridges, etc.). Therefore routing is meaningful even for 18 holes and must ALWAYS be shown explicitly (never omitted). Display as ordered join e.g. 'Lakes + Bridges'; 9-hole shows the single nine 'Back 9'/'Xena'.
- (decision) Routing chip treatment: inline muted text (not a bordered/filled chip). Lightest visual weight.
- (change) Refined row v1 still felt too cramped (line 2 overloaded). Fix to try: move PRICE up to line 1 right (paired with course name); line 2 carries holes · routing · players only. Balances the two lines and frees the name.
- (decision) MOBILE ROW canonical shape (Rayce-directed): 3-zone row. LEFT rail = start time (dominant, bold + AM/PM). MIDDLE = course name on its own line at full middle width (spillover/wrap allowed, never ellipsis); beneath it a condensed line: holes · routing(if known) · 'up to N' group size. RIGHT rail = Book button on top, price-per-adult underneath ('price n/a', muted, when unknown). Every row shows: time, course, holes, routing(if known), up-to-N, Book, price(if known).
- (decision) MOBILE ROW — LOCKED (supersedes earlier line-grouping notes). 3 zones: LEFT rail=start time (bold, dominant, +AM/PM). - (decision) DESKTOP TABLE columns (7): Time | Course | Holes | Routing | Up to | Price | Book. Holes and Routing are separate columns — minimizes row height, single anchor per column. Routing shows '—' when not known (same treatment as unknown price). Time is inline 'H:MM AM/PM' on a single line (no stacked AM/PM) to maximize density.
- (decision) DESKTOP HOLES filter: button group Any | 6 | 9 | 12 | 18. 6 and 12 added because Greenbryre uses those hole counts.
- (decision) DESKTOP PLAYERS filter: button group Any | 1 | 2 | 3 | 4. 'Any' is an explicit option (not just a reset) — when 'Any' is active the booking URL uses the slot's maxGroupSize (not forced to 1). Same visual treatment as Holes filter.
- (decision) DESKTOP COURSE filter: checkboxes for each course. Header row has 'Course' label left-aligned and 'Deselect all' / 'Select all' toggle right-aligned (space between via flex justify-content:space-between). No inline 'clear' link — just the toggle.
- (decision) DESKTOP DATE: clicking the date string in the sidebar opens a calendar popup (dropdown). Prev/next arrows on the date nav still work for day-stepping without opening the calendar. Past dates are visually muted/unclickable.
- (decision) DESKTOP SORT: chronological only (no sort-by-column). Group-by-course toggle groups results by course but each group remains sorted chronologically.
- (decision) DESKTOP LAYOUT v3 refinements: (1) Count summary ('38 tee times · all courses · Mon Jun 29') sits above the column header row in the sticky block — not below it. (2) Calendar popup is position:absolute overlay — does NOT push sidebar content down when opened. (3) Sidebar width increased to 264px so Holes buttons (Any|6|9|12|18) fit on one line without wrapping. (4) Sidebar filter order: Date → Earliest start → Course → Holes → Players → Group by course → Search. (5) Search button at bottom of sidebar — query fires on click, not on every filter change. (6) Slots column header renamed from 'Up to'; each cell reads 'Up to N'.
- (decision) DESKTOP FILTER BEHAVIOR: No Search button. Date change = triggers a new API fetch (new DynamoDB query). All other filters (course, holes, players, earliest start, group by course) = purely client-side, applied instantly to the already-fetched day's data without any network request. This matches the architecture: one GET /api/tee-times?date=D returns the full day; all refinement happens client-side.
- (decision) URL BEHAVIOR: URL is the single source of truth for all view state. Params: date=YYYY-MM-DD, holes=6|9|12|18, players=1|2|3|4, from=HH:MM (24h), courses=slug1,slug2,..., group=course. Omitted param = default: date→today, from→any time (00:00 / omitted), courses→all, holes→any, players→any, group→off (chronological). A shared URL with a specific date always shows that date — no snap-to-today. The URL reflects every active filter so any view is fully shareable and bookmarkable.
- (decision) FRESHNESS INDICATOR: Three colour states based on age of lastUpdated (min scrapedAt across the day). Fresh <20min = green dot ('Updated 3 min ago'). Stale 20min–1hr = amber dot ('Updated 28 min ago'). Very stale >1hr = red dot ('Updated 2 hr ago'). Shown in top bar on both mobile and desktop. Per-course staleness indicator: only shown when 'Group by course' toggle is ON — each course group header shows its own freshness state. When not grouped, only the global indicator is shown.
- (decision) COURSE GROUP HEADER (grouped view): Option A — subtle divider row. Full-width row spanning all columns, background var(--bg) (#f5f6f7), top+bottom border var(--line). Left: course name in small uppercase bold (ink-2). Middle: slot count (ink-3). Right: freshness dot + 'Updated X ago' text in the dot's colour (green/amber/red). Minimal height (~32px), recedes visually so the data rows remain the focus.
- (decision) TABLE STATES: (1) Loading — skeleton shimmer rows replace the table while fetch is in flight; freshness indicator shows 'Updating…' in muted text; subcount line is blank. (2) Empty — subcount shows '0 tee times'; table body replaced with centered card: golf icon + 'No tee times found' + 'There's nothing available for this date with your current filters.' + 'Reset filters' underline link. One generic message covers both filter-too-narrow and no-data-for-date cases. (3) Error — centered card: warning icon + 'Something went wrong' + 'Couldn't load tee times. Check your connection and try again.' + 'Try again' button; freshness indicator shows dash. (4) Stale but loaded — table renders normally; red dot in topbar is the only signal, no interstitial.
- (decision) DATE NAVIGATION BOUNDS: Earliest navigable date = today. Past dates are not navigable — calendar greys out all dates before today (already shown in mock). No need to query past dates: past tee times are already filtered client-side via the shared isPast util (startInstant < now), so yesterday's data would appear empty anyway. Furthest navigable date = max booking window across all courses (the furthest-ahead date any course has scraped data for). Calendar greys out dates beyond that window. If a date beyond the window is loaded via URL query param, the table shows the standard empty state — no special error.
- (decision) VISUAL IDENTITY: Clean neutral grey system with forest green accent pops. Single CSS variable --accent controls all colour. Starting value: #2e6b47 (forest green), --accent-dark: #245538 (hover/pressed), --accent-light: #eaf3ee (checkbox tint, toggle track). Accent applied to: Book button background, calendar selected date, active holes/players toggle buttons, checkbox accent-color, group-by-course toggle (active track). Freshness dots reuse accent for 'fresh' state; amber #e09400 and red #e03030 for stale/very-stale. Typography: system font stack (-apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Helvetica, Arial). Accent is intentionally easy to swap — one variable rethemes everything.
- (decision) VISUAL IDENTITY CONFIRMED: Forest green #2e6b47 approved. Contrast ratio vs white = 6.35:1 — meets WCAG AA for all text sizes. Palette locked.
- (decision) ACCESSIBILITY FLOOR: WCAG AA contrast (met by palette). Full keyboard navigation — tab through sidebar filters, date arrows, Book buttons; calendar grid navigable with arrow keys. Visible focus rings using accent green on all interactive elements. Semantic table markup: <table>/<th scope=col>/<td> so screen readers announce column headers per cell. 44px minimum touch targets on mobile (Book button already locked). Skeleton shimmer respects prefers-reduced-motion (static grey bars instead of animation).
- (decision) KEY FLOWS: (1) 'Rayce, phone in kitchen, Sunday morning' — opens app, today's tee times load immediately with no clicks; scans chronological list using time as the dominant anchor; spots a slot that works; taps Book; booking portal opens in a new tab; completes booking on the course's own portal. (2) 'Rayce shares a filtered view with a friend' — opens app on desktop; steps to next Saturday via date nav; selects 18 holes + 2 players in sidebar, table narrows instantly; copies URL (?date=2026-07-05&holes=18&players=2); sends to friend; friend opens URL and sees the identical filtered view with no setup required.
- (decision) VALIDATION RESOLUTION — decisions: (1) Responsive breakpoint: 768px. Below = mobile layout; 768px+ = desktop sidebar+table layout. (2) Earliest Start widget: horizontal slider, 1-hour increments, range 5 AM–9 PM (16 stops). Default = leftmost (5 AM = no effective filter; from param omitted from URL). Current selection shown as label above thumb ('From 8:00 AM'). URL writes from=HH:MM in 24h when not at default. (3) Mobile filter panel: bottom sheet sliding up from bottom. ALL filters including date live in the sheet. Reason: thumb-reachability — users should not have to stretch to the top of the screen to filter. Contents in order: Date (with full calendar) → Earliest start (slider) → Course (checkboxes) → Holes (toggle group) → Players (toggle group) → Group by course (toggle). Sheet trigger lives at the bottom of the screen. (4) All-courses-deselected: treat as empty state ('No tee times found' + Reset filters restores all). (5) Late-night all-past empty state: generic message is fine ('No tee times found'). No 'try tomorrow' variant needed. (6) Players filter predicate: maxGroupSize >= selected value — slot must accommodate AT LEAST the number of players requested.
